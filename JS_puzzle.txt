1. What gets logged?
javascriptconsole.log(typeof typeof 1);
// Answer: "string"
typeof 1 returns "number" (a string), then typeof "number" returns "string".

2. Array comparison
javascriptconsole.log([] == ![]);
// Answer: true
![] is false (arrays are truthy). Then [] == false converts both: empty array becomes "", false becomes 0, empty string becomes 0, so 0 == 0 is true.

3. Addition mystery
javascriptconsole.log(1 + "2" + "2");     // "122" - left to right, 1+"2" = "12", "12"+"2" = "122"
console.log(1 + +"2" + "2");    // "32" - unary + converts "2" to 2, so 1+2=3, 3+"2"="32"
console.log(1 + -"1" + "2");    // "02" - unary - converts "1" to -1, so 1+-1=0, 0+"2"="02"
console.log(+"1" + "1" + "2");  // "112" - +"1" = 1, 1+"1"="11", "11"+"2"="112"

4. Function hoisting
javascript// Logs: undefined, then 2
The var x = 2 declaration is hoisted to the top of the function scope but not the assignment, so first console.log sees undefined.

5. Tricky truthiness
javascriptconsole.log([] + []);    // "" - both arrays convert to empty strings
console.log([] + {});    // "[object Object]" - [] becomes "", {} becomes "[object Object]"
console.log({} + []);    // "[object Object]" - same as above
console.log({} + {});    // "[object Object][object Object]" - both convert to "[object Object]"
Note: In some contexts like the browser console, {} + [] might be 0 because {} is treated as a code block!

6. The setTimeout classic
javascript// Logs: 3, 3, 3
var has function scope, not block scope. By the time the timeouts execute, the loop has finished and i is 3. Fix with let instead of var.

7. Arrow function context
javascript// Logs: "Hello, undefined"
Arrow functions don't have their own this, they inherit from the enclosing scope. Here, this is probably the global object where name is undefined.

8. NaN weirdness
javascriptconsole.log(NaN === NaN);        // false - NaN is never equal to itself
console.log(Object.is(NaN, NaN)); // true - Object.is() correctly identifies NaN
Use Number.isNaN() or Object.is() to check for NaN!

9. Promise execution order

Promise.resolve().then(() => console.log('3'));

// Answer: 1, 4, 3, 2

10. Async/await with promises
javascriptasync function foo() {
  console.log('1');
  await Promise.resolve();
  console.log('2');
}
console.log('3');
foo();
console.log('4');
// Answer: 3, 1, 4, 2
// Explanation: Sync code (3), foo starts (1), await yields (4 runs), then microtask (2)

11. Promise chain gotcha
javascriptPromise.resolve(1)
  .then(x => x + 1)
  .then(x => { x + 1 })
  .then(x => console.log(x));
// Answer: undefined
// Explanation: Second .then has no return statement, so it returns undefined

12. Temporal Dead Zone (TDZ)
javascriptfunction test() {
  console.log(a);
  console.log(b);
  var a = 1;
  let b = 2;
}
test();
// Answer: undefined, then ReferenceError
// Explanation: var is hoisted (undefined), let is in TDZ until declaration

13. More TDZ
javascriptlet x = x + 1;
// Answer: ReferenceError
// Explanation: x is in TDZ on the right side; can't access before initialization

// Explanation: Function declarations are hoisted entirely, but var bar is undefined when called
